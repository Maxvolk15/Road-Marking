# Project: Road-Marking

## Тема проекта
Контроль дорожной разметки: загрузка фотографий улиц, обнаружение стёртых линий и пробелов, формирование заданий на ремонт.


## Назначение приложения
Приложение предназначено для контроля состояния дорожной разметки. Пользователи смогут загружать фотографии дорог, система будет анализировать их на предмет наличия стёртых линий и пробелов в разметке. На основе анализа формируются задания на ремонт для соответствующих служб. 

## Основные пользовательские сценарии
1. **Просмотр статистики (Dashboard):** Пользователь заходит в систему и видит общее количество загруженных фотографий, количество обработанных снимков и количество открытых задач на ремонт.
2. **Загрузка фотографий (Upload):** Пользователь переходит на экран загрузки, выбирает файл с фотографией улицы, записывает адрес, после чего нажимает кнопку загрузки (имитация).
3. **Просмотр результатов анализа:** Пользователь просматривает список всех фото, их статусы ("Обработано", "В обработке", "Ошибка") и количество обнаруженных дефектов. При клике на фото открывается его детализация.
4. **Просмотр заданий на ремонт:** Пользователь может видеть список всех сгенерированных заданий, привязанных к конкретным фото, с указанием их статуса ("Открыто", "В работе", "Выполнено").

## Реализованные экраны
1. **Главная страница (Dashboard)** - общая статистика системы.
2. **Загрузка (Upload)** - интерфейс для выбора и загрузки изображения.
3. **Анализ (Analysis)** - карточки с фотографиями и их статусом.
4. **Детали фото (Analysis Detail)** - просмотр конкретной фотографии и привязанных к ней заданий на ремонт.
5. **Задания на ремонт (Tasks)** - таблица со списком заданий и их статусами.

## Модель данных (Entity-Relationship)

Система построена на двух основных связанных сущностях:

1. **`Photo` (таблица `photos`)** — фотография участка дороги и статус её обработки ML-моделью:
   - `id` (Integer, Primary Key, autoincrement) — уникальный идентификатор.
   - `image_url` (String(1000)) — URL или путь к файлу изображения.
   - `address` (String(255)) — адрес участка дороги (индексирован).
   - `status` (String(50)) — статус анализа (`processing`, `processed`, `error`).
   - `issues_count` (Integer) — количество обнаруженных дефектов разметки.
   - `created_at` / `updated_at` — метки времени создания и изменения.
   - **Связь:** `tasks` (один-ко-многим к `Task`) с каскадным удалением `cascade="all, delete-orphan"`.

2. **`Task` (таблица `tasks`)** — сформированное задание на проведение дорожно-ремонтных работ:
   - `id` (Integer, Primary Key, autoincrement) — уникальный идентификатор.
   - `photo_id` (Integer, Foreign Key `photos.id` ON DELETE CASCADE) — ссылка на исходную фотографию.
   - `description` (Text) — описание дефекта и необходимых работ.
   - `address` (String(255)) — адрес проведения ремонтных работ.
   - `status` (String(50)) — статус выполнения (`open`, `in_progress`, `completed`).
   - `created_at` / `updated_at` (DateTime with timezone) — метки времени создания и изменения.
   - **Связь:** `photo` (обратная связь многие-к-одному к `Photo`).

## Управление состоянием (State Management)

- **Централизованный контекст `DataContext`:** обеспечивает сквозное реактивное состояние между всеми экранами без необходимости перезагрузки страницы.
- **Хранение в `localStorage`:** изменения (добавленные фотографии, отредактированные или удалённые задания) автоматически сохраняются в браузере и восстанавливаются при обновлении страницы.
- **Сброс данных:** предусмотрена кнопка *«Сброс демо»* на Дашборде для мгновенного возврата к исходным mock-данным.
- **Имитация ML-анализа дорожного полотна:** при отправке формы загрузки фото создается снимок в статусе `processing`, после чего через 2.5 секунды статус переходит в `processed`, вычисляется количество найденных стёртых линий и автоматически создается связанное ремонтное задание.

## Клиентская валидация форм

1. **Форма загрузки фотографии (`UploadPhotoForm`):**
   - **Наличие файла:** проверка выбора изображения перед отправкой.
   - **Формат файла:** допустимы только `image/jpeg`, `image/png`, `image/webp`. При попытке загрузить неподдерживаемый формат отображается понятная ошибка.
   - **Размер файла:** ограничение до 10 МБ с выводом предупреждения при превышении.
   - **Адрес участка дороги:** обязательное поле, проверка длины (не менее 3 и не более 255 символов), индикация ошибок через `error` и `helperText` с валидацией на события `onChange` и `onBlur`.
   - **Предпросмотр изображения:** возможность удалить выбранный файл крестиком и выбрать другой.

2. **Форма создания задания на ремонт (`CreateTaskDialog`):**
   - **Связанный снимок:** выбор фото из каталога либо фиксация при создании из экрана детального анализа.
   - **Описание работ:** обязательное поле от 5 до 500 символов с подробным описанием ошибки при некорректном вводе.
   - **Адрес:** обязательное поле (не менее 3 символов), автоматически предзаполняется адресом выбранного снимка.
   - **Начальный статус:** выбор между «Открыто», «В работе», «Выполнено».

## Состояния отображения данных

Для каждого экрана с данными реализованы три обязательных состояния:
- **Состояние загрузки (`LoadingState` / `Skeleton`):** отображение анимированных скелетонов карточек или таблицы во время получения данных.
- **Состояние ошибки (`ErrorState`):** информативные карточки с описанием проблемы и кнопками «Повторить попытку» или «Назад к списку».
- **Состояние отсутствия данных (`EmptyState`):** тематическая иконка, разъясняющий текст и кнопка сброса фильтра или создания первой записи при пустом результате поиска.

## Анимации и переходы интерфейса

- **Всплывающие уведомления (`Snackbar` + `Alert`):** анимированный всплывающий тост (слайд снизу) информирует пользователя о каждом действии (создание снимка, завершение анализа, создание/удаление задачи, изменение статуса).
- **Плавное появление элементов (`Grow` / `Fade`):** появление карточек дашборда и анализа с каскадной задержкой.
- **Индикатор прогресса (`LinearProgress`):** визуализация этапов обработки кадра (загрузка $\to$ нормализация $\to$ сегментация разметки) во время анализа.
- **Интерактивные переходы состояний:** возможность смены статуса задачи в один клик прямо из таблицы или карточки детализации со сменой цвета чипа.
- **Эффекты наведения (Hover effects):** плавный подъем карточек (`transform: translateY(-3px)`) с увеличением тени.
